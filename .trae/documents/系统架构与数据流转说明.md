基于对代码库的分析，这套系统的技术架构、数据流转及所用技术栈如下：

### 1. 技术栈概览

#### **后端 (Backend)**
*   **框架**: `FastAPI` (高性能异步 Web 框架)
*   **服务容器**: `Uvicorn` (ASGI 服务器)
*   **数据库**: `PostgreSQL` (主业务数据), `Redis` (缓存与消息队列)
*   **ORM**: `SQLAlchemy` (数据库交互), `Alembic` (数据库迁移)
*   **异步任务**: `Celery` (任务队列管理)
*   **文件存储**: `MinIO` (兼容 S3 协议的对象存储)
*   **核心算法**: `MATLAB` (通过 Shell/Batch 脚本被 Python 子进程调用)

#### **前端 (Frontend)**
*   **框架**: `Vue 3`
*   **构建工具**: `Vite`
*   **UI 组件库**: `Element Plus`
*   **状态管理**: `Pinia`
*   **语言**: `TypeScript`

### 2. 系统服务架构 (基于 Docker Compose)
系统由以下 6 个核心容器服务组成：
1.  **frontend**: Nginx 托管 Vue 前端静态资源，反向代理 API 请求。
2.  **backend**: FastAPI 应用服务器，处理 RESTful API 请求。
3.  **celery_worker**: 后台任务执行者，负责拉取队列任务并调用 MATLAB。
4.  **postgres**: 存储用户信息、任务状态、配置参数等结构化数据。
5.  **redis**: 作为 Celery 的 Broker (消息中间件) 和 Backend (结果存储)。
6.  **minio**: 存储用户上传的 `.nd2` 原始文件及分析结果文件。

### 3. 核心数据流转 (任务生命周期)

1.  **上传阶段**:
    *   用户在前端创建任务 -> 前端请求后端获取 **MinIO 预签名 URL (Presigned URL)** -> 前端直接将 `.nd2` 大文件上传至 MinIO (不经过后端服务器，提高效率)。

2.  **提交阶段**:
    *   用户点击“运行” -> 后端将任务 ID 放入 Redis (Celery Queue) -> 更新数据库状态为 `QUEUED`。

3.  **处理阶段 (异步)**:
    *   **Celery Worker** 从 Redis 抢占任务 -> 状态变更为 `RUNNING`。
    *   Worker 从 MinIO 下载数据文件到本地临时目录。
    *   Worker 通过 `subprocess` 调用 **Shell 脚本 (`run_matlab_task.sh`)** 启动 MATLAB 进程。
    *   MATLAB 读取数据进行图像处理分析 -> 输出结果文件 (Excel, CSV, 图像等)。

4.  **完成阶段**:
    *   Worker 捕获 MATLAB 输出日志 -> 监控进度。
    *   处理完成后，Worker 可能会将结果回传至 MinIO (具体视脚本逻辑而定) -> 更新数据库状态为 `SUCCEEDED`。
    *   前端轮询或通过 WebSocket (如果有) 获取最新状态并展示结果。

此架构设计实现了**计算密集型任务 (MATLAB) 与 Web 服务 (FastAPI) 的解耦**，保证了前端交互的流畅性。
